## ⚠️ Risks  
- 🚫 Runtime is unverified. The smoke-start tier was skipped, so nothing has confirmed that the application deploys, starts or serves requests on Java 25.  
- 🖥️ Application-server compatibility: the bytecode now targets Java 25. The branch `summary.md` notes that WildFly 26, the current server line for this project, does not officially support Java 25. Moving to WildFly 27+ means moving to Jakarta EE 10 (`javax` → `jakarta`), which this iteration did not do.  
- 🧬 Classloader-conflict risk. The project already declares the Java EE 7 API set (`org.jboss.spec:jboss-javaee-7.0`, scope `provided`), so the server is expected to supply these APIs. Three of the added artifacts are now packaged in the WAR and may clash with the server's own copies:  
  - `jakarta.inject-api` 1.0.3 (compile): the `javax.inject` API, which the server's CDI provides.  
  - `jakarta.xml.bind-api` 2.3.3 (compile): the JAXB API, used by the JAX-RS XML endpoints.  
  - `jaxb-runtime` 2.3.9 (runtime): a JAXB implementation alongside the server's own.  
  - `jakarta.annotation-api` 1.3.5 is `provided`, so it carries no packaging risk.  
- 🔒 Java-version lock-in: `IO.println` (`java.lang.IO`) only exists on Java 25, and `Locale.of` needs Java 19+. The code can no longer be compiled or run on older JDKs.  
- 🧪 No automated tests were run, so behaviour is verified by compilation only. The `*IT` integration tests that were modified need a WildFly container and were not run.  
- 🔧 The build-plugin upgrades (war 3.5.1, surefire/failsafe 3.5.6) change packaging and test-execution tooling, and their effects have only been checked by a successful build.  
- ℹ️ `maven-compiler-plugin` is not declared, so Maven's default version is used, and the `version.maven.compiler.plugin` property (3.1) is unused.
